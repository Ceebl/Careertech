How this works

Telling a student that most vacancies are never advertised does very little. Making them guess the number first, watching them land on 20%, and then showing them the real figure does a great deal. That gap between what they expected and what is true is the whole activity.

The activity page itself is hosted once, here. Your questions are not stored anywhere — they are squashed down and packed into the link. When someone opens it, their browser unpacks them. That is why the link is so long, and why there is nothing for you to upload.

The three question types

  • Guess a number. A slider, then a scale showing how far off they were. Best for statistics, percentages, salaries, timescales.
  • Pick an option. Multiple choice. You can also fill in what proportion of people picked each one — from your own survey data — and it draws bars.
  • Rate it out of five. Shows a piece of text, they score it, then you reveal the score you would give and why. Best for judging a sample interview answer, CV line, or email.

Using it in a Pathway

Nothing here is sent anywhere, so the activity cannot report a score back to TargetConnect on its own. Tick Give them their answers as text to copy and the results screen produces a plain block of text. Pair the embed with a reflection or evidence field in the same activity and ask students to paste it in — TargetConnect does the recording, and you get something to mark.

Worth knowing

  • The widget never changes height. Everything happens inside one fixed box, so nothing on the page below it shifts as students work through. That matters in TargetConnect, where a growing embed slides down over the Submit button.
  • Nothing is stored. The part of the link after the # never leaves the browser, so your questions are never sent to this server and never appear in any log here.
  • To change a question later, paste your link back into the box at the bottom left, edit it, and swap the link over.
  • Keep the whole link. If it gets cut short in an email or a text box, it will not open. The page will say so rather than showing half an activity.
  • It needs this site to be up. The page is served from here, so if this server is down the embed shows an empty box.
  • Cite your figures. Each question has a source line. A revealed statistic with no source invites an argument you will lose.

Running your own copy

Both this builder and the activity page are plain HTML files with no server behind them, so they will sit on any hosting that serves static files — Kinsta, GitHub Pages, SharePoint, a university web server, anything. There is nothing to install and no database.

Copy this folder structure across, keeping the shape:

brand/ct.css
brand/ct.js
builders/reveal-link-builder.html
w/reveal/index.html

The builder looks for a copy of the activity page alongside itself when it loads. If it finds one, your links point at your own hosting and you are entirely independent. If it does not, they point back at the original. Either way the address it settled on is shown at the bottom of the settings, and you can type a different one in.

If you only want the activity page and not the builder, that single file is all you need — build links here and change the address to yours.
